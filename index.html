Warm up with LINQ

Search, sort and projection

Recall the query journey

Start with a DbSet, describe the matching rows, then execute the query. Choose tracking only when entities need to be modified in the same context.

1Define

Where, OrderBy and Select express the query.

2Execute

ToListAsync runs the query, returning objects or projected values.

3Use

Print the loaded list. Printing does not re-run the query.

Example · familiar query
var query = db.Items.AsNoTracking()
    .Where(i => i.IsActive && i.Stock > 0);
var rows = await query.ToListAsync();

Where compares rows; Select determines the result shape. OrderBy establishes primary ordering; ThenBy breaks ties. CountAsync and AnyAsync return scalars, not entity lists.

Compose and page queries

Dynamic filters and SQL preview

Build filters without executing them

The shop needs a searchable catalog. A customer may select any combination of keyword, category, supplier, maximum price and availability. Don't write a different query for every combination.

Query composition
IQueryable<Item> query = db.Items.AsNoTracking();
if (categoryId > 0)
    query = query.Where(i => i.CategoryId == categoryId);
// Continue adding filters; execute once you know the result needed.
Operator Purpose
IQueryable<Item> Composable provider-backed query
CountAsync Execute a count of the matches before paging
Skip(n) Skip n ordered matches
Take(10) Limit a page to ten rows
ThenBy(Id) Stable tie-breaker
ToQueryString Debugging preview; does not fetch rows
One-based page number
var pageQuery = query.OrderBy(i => i.UnitPrice)
    .ThenBy(i => i.Id)
    .Skip((page - 1) * pageSize)
    .Take(pageSize);

Always order before Skip/Take and use a unique tie-breaker. Count before applying the page limit.

Join related tables

Project names and values

From foreign keys to readable reports

Option 1 currently prints CategoryId and SupplierId. A customer report needs names. Use a familiar SQL JOIN and its LINQ equivalent.

SQL · three related tables
SELECT i.Name, i.UnitPrice, c.Name AS CategoryName, s.Name AS SupplierName
FROM dbo.Items AS i
JOIN dbo.Categories AS c ON i.CategoryId = c.Id
JOIN dbo.Suppliers AS s ON i.SupplierId = s.Id;
LINQ · one join
var query = db.Items.AsNoTracking()
    .Join(db.Categories,
        i => i.CategoryId,
        c => c.Id,
        (i, c) => new { Item = i, CategoryName = c.Name });
Join argument Meaning
db.Categories Second query source
i => i.CategoryId Key from Items
c => c.Id Matching key from Categories
(i, c) => new { ... } Shape the result for matching rows

The second Join connects the supplier key from that intermediate result to Supplier.Id. Project only values needed in the final report; no navigation properties or Include required.

Update multiple items

Tracking and UpdateRange

One context can coordinate multiple changes

Run option 11, supplying the two practice item IDs and stock 12. It retrieves tracked entities, edits both, then saves once. No UpdateRange is required for this tracked pattern.

Tracked collection update
var items = await db.Items
    .Where(i => i.Id == firstId || i.Id == secondId).ToListAsync();
if (items.Count != 2) return;
foreach (var item in items) item.Stock = stock;
await db.SaveChangesAsync();
Approach What EF Core knows
Tracked query + assignment The context tracks original and current values; save detects changes
AsNoTracking + assignment The objects are not tracked; save alone does not persist their modifications
UpdateRange(complete objects) Explicitly marks existing entities for updates; may mark writable properties modified

SaveChangesAsync returns the number of state entries written, not the number of SQL commands. Several operations can be coordinated in one unit of work.

SESSION 08 · STEP 11 / 12 · 12 MINUTES

Edit in a new context

Disconnected update

The edit page is not one long-lived DbContext

Imagine a web user opens an edit page, waits, changes the price, and presses Save later. The read request is already finished when editing occurs.

ARead context

Read the row without tracking, display it, dispose A.

…Time passes

User enters a new price. Only the ID and permitted value are needed for the save.

BSave context

Retrieve by ID again, change price, save, dispose B.

Object identity is not a database row. Disposing the old DbContext stops its tracking; the new context has its own tracker. Re-query with the primary key rather than sending all edited data indiscriminately.

Practise the two-request pattern
